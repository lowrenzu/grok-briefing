DEMANDE À TRANSMETTRE À L'AGENT D'ANNA
=====================================

Bonjour,

Peux-tu mettre en ligne une petite application sur le serveur, sur
https://jarvis.gabrielleorpel.com ? Elle n'a AUCUNE dépendance à installer
(Python 3 standard seul : ni pip, ni npm, rien à compiler), et elle gère
elle-même son certificat HTTPS via Caddy.

Important : **je ne te donnerai aucun mot de passe ni aucun identifiant.**
C'est volontaire. L'application s'installe « vide » et c'est moi qui saisirai
mes identifiants moi-même, dans mon navigateur, à la fin. Le seul chose que
j'attends de toi, c'est un code de 8 caractères affiché à la fin (voir point 4).


1. DNS (prérequis absolu)
-------------------------
Chez le gestionnaire du domaine gabrielleorpel.com :

    A      jarvis   <adresse IPv4 de ce serveur>
    AAAA   jarvis   <adresse IPv6, si le serveur en a une>

Vérification :  dig +short jarvis.gabrielleorpel.com
                → doit renvoyer l'IPv4 de ce serveur.

Le domaine principal existe déjà ; c'est seulement le sous-domaine « jarvis »
qui manque. Sans lui, aucun certificat ne peut être émis.


2. Récupérer le code
--------------------
    cd /root
    curl -sL https://codeload.github.com/lowrenzu/grok-briefing/zip/refs/heads/arena/b5439b0b-grok-briefing -o jarvis.zip
    python3 -m zipfile -e jarvis.zip .
    cd grok-briefing-arena-b5439b0b-grok-briefing

BRANCHE À UTILISER : arena/b5439b0b-grok-briefing
  ⚠️ Ne pas prendre la branche par défaut (`film`) : elle est en retard et ne
  contient ni le module `prefs.py`, ni `setup.py`, ni les protections d'accès.

Le dépôt est public : aucun secret ne doit y être écrit.


3. Installer — SANS identifiants
--------------------------------
    sudo JARVIS_SETUP_PAGE=1 bash install.sh

Le script installe python3 et Caddy, copie l'application dans /opt/jarvis
(utilisateur système `jarvis`), crée /opt/jarvis/data (700, un sous-dossier par
compte), écrit un service systemd qui écoute sur 127.0.0.1:4700, et ajoute un
bloc au Caddyfile (avec sauvegarde s'il existe déjà).

Avec JARVIS_SETUP_PAGE=1 :
  - il ne pose AUCUNE question et n'écrit aucun identifiant ;
  - le service démarre volontairement « non configuré » : il n'affiche pas
    l'application, seulement une page de premier réglage ;
  - donc rien n'est exposé pendant ce temps.

Si un autre frontal web (nginx/apache) tient déjà 80/443 :
    sudo JARVIS_SETUP_PAGE=1 JARVIS_SKIP_CADDY=1 bash install.sh
puis ajouter soi-même le reverse proxy vers 127.0.0.1:4700.


4. CE QUE J'ATTENDS DE TOI : le code d'installation
---------------------------------------------------
À la fin, le script affiche un code de 8 caractères, ou bien :

    journalctl -u jarvis -n 40

Transmets-moi UNIQUEMENT ce code (8 lettres/chiffres). Il ne vaut qu'une fois
et ne donne accès à rien : il sert juste à ouvrir la page de réglage pour moi.

Ne me transmets aucun autre secret, et ne crée aucun mot de passe.


5. Vérifications à faire et à me transmettre
--------------------------------------------
    dig +short jarvis.gabrielleorpel.com     → IPv4 du serveur
    systemctl is-active jarvis               → active
    curl -I https://jarvis.gabrielleorpel.com
        → 302 vers /setup  (et certificat valide)
    curl -I http://127.0.0.1:4700
        → 302 vers /setup
    journalctl -u jarvis -n 40

La page /setup DOIT s'afficher. Si l'application répond autre chose, arrête-toi
et envoie-moi la sortie de `journalctl -u jarvis -n 50`.


6. Après (c'est moi qui le fais)
--------------------------------
J'ouvrirai https://jarvis.gabrielleorpel.com/setup, je saisirai le code, mon ID
client Google, mon code secret et mon adresse Gmail. La page se referme
définitivement ensuite, et l'application devient privée (connexion Google
obligatoire).

Il restera alors à autoriser cette adresse de retour dans Google :
    https://jarvis.gabrielleorpel.com/auth/callback
(je m'en occupe aussi).


7. À ne pas faire
-----------------
  - ne pas exposer le port 4700 sur Internet (Caddy seul en frontal) ;
  - ne pas mettre JARVIS_AUTH=off : c'est l'ouverture totale, pour du
    développement local uniquement ;
  - ne pas écrire de secret dans le dépôt ;
  - ne pas modifier config.json à la main : il se remplit tout seul par la page.

Persistance : les données vivent dans /opt/jarvis/data (notes par compte, noms,
teintes) et /opt/jarvis/access.json. Une mise à jour (relancer install.sh) ne
les touche pas : le rsync du script les exclut. C'est vérifié par un test du
dépôt (tests/test_install_keep.py).


Merci ! Dis-moi juste : « DNS fait », puis le code de 8 caractères.
