MESSAGE À TRANSMETTRE À L'AGENT D'ANNA
=====================================

Objet : mettre JARVIS en ligne sur https://jarvis.gabrielleorpel.com


CONTEXTE TECHNIQUE
------------------
Application Python 3, sans aucune dépendance (bibliothèque standard seule) :
pas de pip, pas de npm, rien à compiler. Elle sert une interface web et
appelle éventuellement une API d'IA.

Dépôt public :  https://github.com/lowrenzu/grok-briefing
BRANCHE À UTILISER : arena/b5439b0b-grok-briefing

  ⚠️ Ne PAS prendre la branche par défaut (`film`) : elle est en retard et ne
  contient pas le module `prefs.py` ni les dernières protections d'accès.

Le dépôt est PUBLIC : aucun secret ne doit y être écrit (GitHub refuserait
le push de toute façon). Les identifiants vont uniquement dans
/opt/jarvis/config.json, en chmod 600.


1. DNS (prérequis absolu)
-------------------------
Chez le gestionnaire du domaine gabrielleorpel.com :

    A      jarvis   <adresse IPv4 du serveur>
    AAAA   jarvis   <adresse IPv6, si le serveur en a une>

Vérification :  dig +short jarvis.gabrielleorpel.com
                → doit renvoyer l'IPv4 du serveur

Le domaine principal existe déjà ; c'est seulement le sous-domaine « jarvis »
qui manque. Tant qu'il manque, aucun certificat HTTPS ne peut être émis.


2. Récupérer le code
--------------------
    cd /root
    curl -sL https://codeload.github.com/lowrenzu/grok-briefing/zip/refs/heads/arena/b5439b0b-grok-briefing -o jarvis.zip
    python3 -m zipfile -e jarvis.zip .
    cd grok-briefing-arena-b5439b0b-grok-briefing


3. Installer
------------
    sudo bash install.sh

Ce que fait le script :
  - installe python3 et Caddy (certificat HTTPS automatique, Let's Encrypt) ;
  - copie l'application dans /opt/jarvis (utilisateur système `jarvis`) ;
  - crée /opt/jarvis/data (700) : un sous-dossier par compte ;
  - écrit un service systemd `jarvis` qui écoute sur 127.0.0.1:4700 ;
  - ajoute un bloc au Caddyfile (sauvegarde d'abord s'il existe déjà) ;
  - n'ouvre pas le port 4700 sur Internet.

Le script est rejouable : relancé, il met simplement à jour l'application.
Il posera 3 questions, réponses au point 4.

Si un autre frontal web (nginx/apache) tient déjà 80/443 :
    sudo JARVIS_SKIP_CADDY=1 bash install.sh
puis ajouter soi-même le reverse proxy vers 127.0.0.1:4700.

5. Vérifications à faire et à me transmettre
--------------------------------------------
    dig +short jarvis.gabrielleorpel.com          → IPv4 du serveur
    systemctl is-active jarvis                    → active
    curl -I http://127.0.0.1:4700                 → 302 vers /auth/login
    curl -I https://jarvis.gabrielleorpel.com     → 302 vers /auth/login
                                                    + certificat valide
    journalctl -u jarvis -n 30

La dernière commande doit afficher une ligne du type :

    Accès : connexion Google obligatoire (1 adresse(s)) · administrateur …

Si elle affiche « Accès : ouvert (aucune connexion demandée) », quelque chose
désactive la porte : chercher JARVIS_AUTH=off dans l'environnement, ou un
config.json absent. **Ne pas laisser le service en ligne dans cet état** :
sans la porte, les notes sont accessibles à qui connaît l'adresse.


6. À ne pas faire
-----------------
  - ne pas exposer le port 4700 directement sur Internet (Caddy est le seul
    frontal, JARVIS reste en 127.0.0.1) ;
  - ne pas lancer Caddy en mode `autocert` sur un autre port 443 en parallèle ;
  - ne pas écrire les secrets dans le dépôt, même temporairement ;
  - ne pas mettre JARVIS_AUTH=off sur un serveur accessible depuis Internet.

Persistance (important)
------------------------
Les données vivent dans /opt/jarvis/data (700) : un sous-dossier par compte
(notes), plus les noms et teintes choisis. access.json garde la liste des
comptes autorisés.

Une mise à jour (relancer install.sh) NE TOUCHE PAS à ces données : le rsync du
script exclut data/, access.json, config.json et les captures. C'est vérifié par
un test du dépôt (tests/test_install_keep.py).

Sauvegarde manuelle côté utilisateur : ⚙ Réglages → « Télécharger mes notes »
(archive .zip de ses propres fichiers, jamais ceux d'un autre compte).


Deux exceptions possibles, utiles à connaître :
  - JARVIS_DATA_DIR : dossier racine des données (par défaut /opt/jarvis/data) ;
  - JARVIS_NOTES_DIR : dossier de notes du propriétaire (par défaut
    examples/demo-notes, soit les 25 notes de démonstration).
